# Releases

The spec's history stopped at 0.43.0; rows from 0.44.0 on come from the commit log.[^git-log]
The authoritative version is the latest git tag (also stated in `CLAUDE.md`).

| Version | Date | Changes |
|---------|------|---------|
| 0.57.0 | 2026-11-22 | Added: hidden `ccp harness` (`list`, `check`, `sync`, `remove`) for custom harness plugins without an embedded JS VM — supports declarative TOML manifests (`~/.ccp/harnesses/<id>.toml`) and stdin/stdout JSON executables (`~/.ccp/harnesses/<id>` or `ccp-harness-<id>` on absolute `PATH` dirs) producing a validated `HarnessPlan` executed through ccp's copy ledger (`~/.ccp/state/harnesses/<id>.json`), symlink guards, and output-style carrier ledger ([decision](/decisions/harness-plugins-toml-and-exec.md)); integrated into `followHarnesses`, `ccp reset`, and `ccp doctor`. Fixed: `syncCopies` checks `os.Lstat` + `IsRegular()` before reading/removing so symlinks and non-regular files are never adopted or deleted; `syncStyleCarriers` isolates carrier ownership across harness groups. |
| 0.56.0 | 2026-11-20 | Added: `agy` accounts (`ccp account add <name> [<profile>] --harness agy`), keeping file-based tokens in `~/.gemini/antigravity-cli-ccp-<name>/` launched via `ccp run` with `--app_data_dir` and `SSH_CLIENT`, merged `settings.json`, and quota reads via `agy -p /usage --output-format json` ([agy accounts decision](/decisions/agy-accounts-file-token-mode.md)); `ccp account` and `ccp status` show a `HARNESS` column and `"harness"` in JSON. Added: `ccp account` text output now shows unmanaged logins (`Other logins (not accounts)`: Claude global, Claude profile logins, and macOS plain `agy`) read-only with per-kind footer hints and `~/.ccp/state/usage/<key>.json` caching, while `ccp status`, `--account auto`, and `ccp account --json` stay managed-only. Added: `ccp doctor` (macOS) warns on orphan `Claude Code-credentials-<8 hex>` Keychain items (attribute-only, never `--fix`). |
| 0.55.1 | 2026-11-18 | Docs: the ccp skill gets an "Accounts and pools" playbook (pool model, adding accounts, `ccp use --accounts`, a pool per client, how auto picks, moving and removing accounts, troubleshooting) and triggers on account requests. |
| 0.55.0 | 2026-11-18 | Added: `ccp use <profile> --accounts` sets a project folder up so plain `claude` there picks the profile's account with the most limit left: it writes the `.ccp/bin/claude` shim, puts `.ccp/bin` on PATH through `mise.toml` `_.path` (or `.envrc` `PATH_add`) and adds `.ccp/` to `.git/info/exclude`. `ccp run --account auto --or-profile` keeps a session that is already on an account and runs on the profile while no account is logged in. The shim starts the real `claude` from `mise which`, never a mise shim, which would reset `CLAUDE_CONFIG_DIR` ([anti-pattern](/anti-patterns/mise-shim-in-claude-wrapper.md)). |
| 0.54.0 | 2026-11-18 | Added: `ccp account` — Account is now the sixth user-facing concept (the budget rose from five to seven; [decision](/decisions/account-concept.md)). `ccp account` / `account list [--json]` lists accounts with profile, email and plan usage, and with none says how to add one; `ccp account add <name> [<profile>]` creates an account for a profile (default: the current one), logged out until `ccp run --account <name>` and `/login`. |
| 0.53.2 | 2026-11-18 | Fixed: `ccp run --help` (and `-h` before `--`) prints the help instead of failing with "unknown flag before --"; a help flag after `--` still goes to the command. `ccp hub list` and `hub add` help and the invalid-type error name every hub type (`output-styles`, `settings-templates`), and `hub list` points to `ccp bundle list`. `ccp status --help` describes the accounts table. |
| 0.53.1 | 2026-11-18 | Fixed: `ccp use` removes a `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` line left by an older ccp in the `mise.toml` or `.envrc` it updates ([activation](/architecture/activation.md)). Docs: when the old alias prompted, and a new [anti-pattern](/anti-patterns/add-dir-profile-folder.md) against it. |
| 0.53.0 | 2026-11-18 | Fixed: `ccp config shell` no longer prints the `claude --add-dir "$CLAUDE_CONFIG_DIR"` alias and `ccp use` no longer writes `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD`. Claude Code loads the profile's `CLAUDE.md` and rules from `CLAUDE_CONFIG_DIR`; since Claude Code 2.1.326 the added folder asked for workspace trust on every start ([activation](/architecture/activation.md)). Remove the alias from existing shell configs (it causes the prompt); an old env var line in a project env file is harmless and can be deleted by hand. |
| 0.52.0 | 2026-11-18 | Added: accounts — one profile under several Claude logins. `--account <name>` on the hidden `run`, `session` and `env` uses `~/.ccp/accounts/<name>/`, a folder with its own login that links every other profile entry; a named account brings its own profile, and `run` defaults its command to `claude`. `--account auto` picks, among the profile's accounts, the one with the most plan limit left (Claude's usage endpoint, cached 5 minutes, else least recently used); `ccp status` lists accounts with their usage. Opt-in `ccp migrate --accounts [--dry-run]` moves each profile's existing login into the account of the same name, refused while Claude Code runs on it, and keeps MCP server tokens already in the account ([accounts decision](/decisions/accounts-as-activation-option.md)). Supersedes [API keys are per-profile](/decisions/api-keys-per-profile.md). Fixed: a command error prints once. |
| 0.51.0 | 2026-11-12 | Added: hidden `ccp agy sync` mirroring a profile into Antigravity CLI (`~/.gemini/config`): `AGENTS.md` linked to `CLAUDE.md`, the output style in `GEMINI.md`, skills linked per item, agents and rules written as converted copies with agy frontmatter; agy follows `use -g`, link/unlink and bootstrap after the first sync ([agy](/features/agy.md)). Changed: opencode's copy ledger is shared code. |
| 0.50.0 | 2026-11-06 | Added: `ccp source update` relinks a shadow whose item moved upstream (`skills/x` to `.claude/skills/x`) and, on every run, lists each installed item it did not reach (a hub copy, a foreign link, an item missing from the hub or gone upstream) with its fix command; `ccp install` accepts an item by its harness path in the clone (`.claude/skills/x`) ([source system](/features/source-system.md)). omp: a two-layer harness-aware sync skill, and the zero-LLM sync honors `~/.omp/agent/config.yml` `agentModelOverrides` and `ignoredSkills` ([omp](/features/omp/overview.md)). Fixed: unlinking a bundle no longer deletes the profile's direct link of the same name ([bundles](/features/bundles.md)); symlinked hub items stay inside `~/.ccp` on `ccp omp sync`. |
| 0.49.1 | 2026-10-21 | Fixed: `doctor` no longer counts files the source repo's git ignores (a `__pycache__/` written when a skill's script ran) as a local edit, so `doctor --fix` turns those hub copies into shadows instead of leaving them stale ([shadow source items](/decisions/shadow-source-items.md)). |
| 0.49.0 | 2026-10-21 | Added: an `output-styles` hub item type; the selected style is carried into omp, pi and opencode ([output styles](/features/output-styles.md)); `ccp install --clone` for an editable local copy.
